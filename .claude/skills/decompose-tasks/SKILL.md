# 任务拆解（供「精力助手」导入）

把用户指定的 md 内容，用**真实理解**（而非关键词匹配）拆成有序任务，写入 inbox，供精力助手自动导入并按精力节律排程。

## 输入

- 用户给出 md 文件路径 / 多个路径 / 文件夹 → 直接用
- 只给文件名 → 先用 glob 查找；找不到再询问
- 没给 → 询问要拆哪个文件/文件夹

## 拆解方法（核心：读懂内容，不是匹配标题）

对每个「可独立执行的单元」生成一条任务，字段含义：

- `title`：一句话、可执行的动作（不是章节名）。例：`完成多表 JOIN 的 5 道练习`，而非 `第三章`。
- `type`：
  - `deep` 深度：需要理解、推导、综合运用（学习新知、解题、深度分析）
  - `creative` 创意/发散：头脑风暴、创意写作、构思方案、发散联想（精力低唤醒的清晨/深夜更旺）
  - `routine` 常规：记忆、复习、整理、抄录、浏览、归档
  - `sprint` 冲刺：有明确期限/紧急交付
- `load`（用脑量，按**内容真实认知难度**，不是标题）：
  - `低`：纯记忆/抄录/过一遍概念，几乎不需思考
  - `中`：理解并练习单一知识点，或基础应用
  - `高`：多知识点综合、需要推导/设计/深度思考
  - **务必结合科目本身判断**。例如 SQL：基础 SELECT/WHERE=低；JOIN+子查询+聚合=中；窗口函数+递归 CTE+事务隔离/索引优化=高。不要被"学习/练习"这类词骗了——"练习窗口函数"是高，"练习 SELECT 语法"是低。
- `estMin`：真实可行的分钟数（别虚高也别低估，练习类按题量估）。
- `priority`：有期限或属前置依赖 → `high`；可延后 → `low`；其余 `medium`。

**排序**：输出顺序 = 建议执行顺序——先基础后进阶、先概念后练习、先输入后输出、先前置依赖后结果。

## 输出

写入 `inbox/tasks.json`（UTF-8，**严格遵循下方格式**）。

inbox 位置：精力助手项目根目录（含 `index.html` 的目录）下的 `inbox/` 子目录。默认绝对路径：

`C:\Users\everglow\my-project\brain-gears\inbox\tasks.json`

（若该目录不存在则先创建；若项目已移动，用 glob 找 `index.html` 定位后写入其同级 `inbox/tasks.json`，并告知用户新路径。）

```json
{
  "source": "原始 md 文件名或来源说明（用于工具去重）",
  "tasks": [
    {
      "title": "一句话可执行动作",
      "type": "deep | creative | routine | sprint",
      "load": "低 | 中 | 高",
      "estMin": 45,
      "priority": "high | medium | low"
    }
  ]
}
```

多个 md 文件/文件夹时：合并为一个 `tasks.json`，每条任务的 `source` 写各自来源文件名。

## 收尾（务必简短）

报告三行即可，不要长篇：
1. 已写入的绝对路径
2. 共 N 条任务、难度分布（低x / 中x / 高x）
3. 建议先做哪一条 + 一句提醒「在精力助手点「重新读取 inbox」或刷新即可看到」

## 注意

- 不要用关键词正则猜难度——要读懂每段在教什么、练什么，再判 `load`。
- 输出必须是合法 JSON（UTF-8，无注释、无尾逗号）。
- 不要改动精力助手的其它文件，只写 inbox/tasks.json。
