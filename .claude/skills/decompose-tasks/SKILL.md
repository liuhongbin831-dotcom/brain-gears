# 任务拆解（供「精力助手」导入）

把用户指定的内容（md/txt/pdf 文件、文件夹，或一段自然语言描述），用**真实理解**（而非关键词匹配）拆成有序任务，写入 inbox，供精力助手自动导入并按精力节律排程。

## 输入（按优先级判断来源）

1. **文件路径**：一个或多个 md/txt/pdf 路径 → 逐个读，合并为一个 tasks.json。
2. **文件夹**：给出目录 → 读目录下所有可读文件（md/txt/pdf），合并为一个 tasks.json（每条任务的 source 写各自来源文件名）。
3. **自然语言描述**：参数不是存在的路径、glob 也找不到文件时，把**整段话当作任务描述**来拆（见下方「自然语言识别」）。
4. **没给** → 询问：要拆哪个文件/文件夹，或有什么描述想变成任务。

## 自然语言识别（rest 恢复 vs 工作）

自然语言里可能同时混着「工作」和「恢复」。按语义分两类：

- **`rest` 恢复/充电**：冥想、正念、散步、午睡/小睡、拉伸/活动身体、泡澡、听音乐放松、纯休息、呼吸练习……这些是**给大脑/身体回血**的活动，不是产出性工作。
- **工作/学习**：其余产出性活动（写、读、练、整理、开会、交付等）。

判断标准：问「这是在**产出**，还是在**恢复**？」恢复 → `rest`；产出 → 按工作类型（deep/creative/routine/sprint）分类。

## 拆解方法（核心：读懂内容，不是匹配标题）

对每个「可独立执行的单元」生成一条任务，字段含义：

- `title`：一句话、可执行的动作（不是章节名）。例：`完成多表 JOIN 的 5 道练习`，而非 `第三章`。
- `type`：
  - `deep` 深度：需要理解、推导、综合运用（学习新知、解题、深度分析）
  - `creative` 创意/发散：头脑风暴、创意写作、构思方案、发散联想（精力低唤醒的清晨/深夜更旺）
  - `routine` 常规：记忆、复习、整理、抄录、浏览、归档
  - `sprint` 冲刺：有明确期限/紧急交付
  - `rest` 恢复：冥想/散步/午睡/拉伸/纯休息等回血活动（挡位1，排入休息时段，不计工作）
- `load`（用脑量，按**内容真实认知难度**，不是标题）：
  - `低`：纯记忆/抄录/过一遍概念，几乎不需思考
  - `中`：理解并练习单一知识点，或基础应用
  - `高`：多知识点综合、需要推导/设计/深度思考
  - `rest` 一律 `低`（恢复本就不费脑）。
  - **务必结合科目本身判断**。例如 SQL：基础 SELECT/WHERE=低；JOIN+子查询+聚合=中；窗口函数+递归 CTE+事务隔离/索引优化=高。不要被"学习/练习"这类词骗了——"练习窗口函数"是高，"练习 SELECT 语法"是低。
- `estMin`：真实可行的分钟数（别虚高也别低估，练习类按题量估；休息类按描述估，如"午睡20分钟"→20）。
- `priority`：有期限或属前置依赖 → `high`；可延后 → `low`；其余 `medium`。休息类默认 `low`（除非用户点名"现在就要休息"）。

**排序**：输出顺序 = 建议执行顺序——先基础后进阶、先概念后练习、先输入后输出、先前置依赖后结果；工作在前，休息穿插/在后。

## 输出

写入 `inbox/tasks.json`（UTF-8，**严格遵循下方格式**）。

inbox 位置：精力助手项目根目录（含 `index.html` 的目录）下的 `inbox/` 子目录。默认绝对路径：

`C:\Users\everglow\my-project\brain-gears\inbox\tasks.json`

（若该目录不存在则先创建；若项目已移动，用 glob 找 `index.html` 定位后写入其同级 `inbox/tasks.json`，并告知用户新路径。）

```json
{
  "source": "原始来源说明（用于工具去重）",
  "tasks": [
    {
      "title": "一句话可执行动作",
      "type": "deep | creative | routine | sprint | rest",
      "load": "低 | 中 | 高",
      "estMin": 45,
      "priority": "high | medium | low"
    }
  ]
}
```

多个文件/文件夹时：合并为一个 `tasks.json`，每条任务的 `source` 写各自来源文件名（自然语言来源写 `自然语言` 或用户给的一句话说明）。

## 收尾（务必简短）

报告三行即可，不要长篇：
1. 已写入的绝对路径
2. 共 N 条任务、难度分布（低x / 中x / 高x），其中恢复 rest 几条
3. 建议先做哪一条 + 一句提醒「在精力助手点「重新读取 inbox」或刷新即可看到」

## 注意

- 不要用关键词正则猜难度——要读懂每段在教什么、练什么，再判 `load`。
- 恢复类活动（冥想/散步/午睡/拉伸）一律判 `rest`，别当成 `routine`。
- 输出必须是合法 JSON（UTF-8，无注释、无尾逗号）。
- 不要改动精力助手的其它文件，只写 inbox/tasks.json。
